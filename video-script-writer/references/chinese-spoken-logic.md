# 中文事实口播逻辑

中文口语化不是给书面稿加“其实”“说白了”“你知道吗”，也不是把专业内容写成网络腔。它首先要改变听众接收信息的顺序，然后才是缩短句子。

仅在最终口播语言为中文时读取并执行本参考。

## 两遍重写，不要一步润色

### 第一遍：重排听觉逻辑

先不用管句子是否漂亮，把每一段改成听众一次能跟上的顺序：

    谁遇到了什么 → 做了什么 → 发生了什么 → 这说明什么 → 接下来该怎么决定

不是每段都要五步齐全，但不要先抛抽象结论，再倒回去解释人物、动作和条件。

具体规则：

1. **先给人和动作，再给概念。** 先说“工程师把训练搬到云端”，再说这叫“云边分工”。
2. **条件在第一次理解事实时出现。** “宣布最多覆盖 68000 人”要一次说完整，不要先说“发给 68000 人”，下一句再纠正“其实只是计划”。
3. **结果和意义分开。** 先说来源实际披露了什么，再用新句子解释它能说明什么。
4. **案例和建议分开。** 先结束“这家公司做了什么”，再明确转入“如果别的企业要试，可以怎么做”。不要让建议看起来像案例公司的实施记录。
5. **时间顺序不是因果链。** “试点之后宣布推广”可以说；“因为试点，所以决定推广”必须有对应因果证据。
6. **一段只回答一个听觉问题。** 段落结束时，听众应该能用一句话复述刚刚知道了什么。
7. **下一段回答上一段自然产生的问题。** 不用“下面进入第二部分”宣布结构。

### 第二遍：改成能说出口的句子

逐句处理，不保留报告体句法：

1. **一句只承担一个主要动作或判断。** 来源、事实、解释、边界不要全部塞进同一句。
2. **主语尽量是人、公司或系统，谓语尽量是动作。** 少用“实现、形成、进行、完成、构建”加抽象名词。
3. **把名词重新变成动词。** “进行权限审计”可改成“先看清谁能读到哪些数据”；“形成可比较证据”可改成“把使用前后的结果放在一起看”。
4. **专业词放在动作之后解释。** 先讲它怎么跑，再告诉听众这个架构叫什么。
5. **清单超过三项时先找共同问题。** 能改成连续动作、判断题或两个关口，就不要一口气念五个名词。
6. **数字要让耳朵分得清对象。** 数字旁边带上人群、时间窗、平均/最多和来源性质；不要把不同分母的数字连成一串。
7. **长限定拆成相邻短句。** 边界仍要靠近事实，但“靠近”不等于必须挤进同一个长句。
8. **保留自然停顿。** 逗号不是无限续写工具；需要第二口气才能说完的句子，应拆开或登记合理例外。

## 把审核边界融进事实，不要朗读审核过程

事实口播需要边界，但不应反复出现“注意”“边界要说清楚”“按某某口径”“这里必须说明”。

优先使用一次成形的表达：

- 不说：“公司向 68000 人推广。注意，这是计划，不是已经部署。”
- 说：“公司宣布了一项推广计划，最多覆盖 68000 人。当时公布的是计划，不是完成数字。”

- 不说：“效果是节省 90%。但边界要说清楚，这不是总体成本。”
- 说：“案例称，本地数据存储成本节省超过 90%。这个数字只对应存储，不是整个项目的总成本。”

来源归因也要贴着事实自然出现：

- 公司或供应商自报：“按公司披露”“微软在客户案例中称”。
- 奖项或活动材料：“据奖项介绍”。
- 不确定或冲突：“现有公开材料用了两个数字，因此无法确定当前人数。”

不要为了展示严谨，把未采用数字、检索过程、来源等级和冲突日志全部讲入口播。

## 抽象表达的口语替换方向

不要机械替换固定词，而要恢复动作关系：

| 报告体 | 中文口语方向 |
| --- | --- |
| 按算力、延迟和数据边界做分工 | 训练放哪儿，看算力和数据；推理放哪儿，看现场能等多久 |
| 建立人工接管和失败回退机制 | 系统拿不准就叫人；做错了还能退回上一版 |
| 形成可比较、可追踪的证据 | 把使用前后放在一起看，而且以后能查到原始记录 |
| 推进规模化部署 | 先给哪些人用、一次放多少、出了问题谁收回来 |
| 治理与变革工程配套 | 权限谁批、问题谁管、员工不会用时谁来帮 |

这些是改写方向，不是必须复用的模板句。

## 三类必须重写的句子

### 1. 先误导、后纠正

原句：

> Walmart 把商店开进了 Gemini。注意，这是宣布计划，不是当天就能下单。

重写方向：

> Walmart 宣布，准备把自家的购物能力接进 Gemini。先在美国上线，但当时公布的还是计划。

### 2. 抽象名词堆叠

原句：

> 根据算力、延迟和数据边界，把训练和推理放在不同环境。

重写方向：

> 训练和推理，不一定非得放在一个地方。训练更吃算力，就放到算力方便增加的地方；推理怕延迟，就留在产线旁边。

### 3. 咨询报告式建议

原句：

> 先用受控试点形成可比较的证据，再决定向哪些岗位、以什么节奏扩大。

重写方向：

> 先别急着给全公司发许可证。找一小批真正会用到的人，看看用了前后到底差多少。账看明白了，再决定先给谁、一次放多少。

## 中文朗读闸门

定稿前必须真的按正常语速朗读，并逐项检查：

1. 听众第一次听到数字时，是否已经知道它说的是谁、哪段时间、平均还是最多；
2. 是否存在要听到下一句，才发现上一句理解错了的“先说满、后纠正”；
3. 每段能否用一句日常中文复述；不能复述，说明概念还没有落到动作；
4. 是否连续出现四个以上并列名词、职责或门槛；有就重组，不只换标点；
5. 是否有一句话需要两口气，或朗读中途忘了主语；有就拆句；
6. “注意、口径、边界、复核、独立验证、实施路径”等审核词是否真的需要让观众听见；
7. 是否靠语气词假装口语化；删掉语气词后仍然自然，才算真正口语；
8. 结尾是否说完判断就停，没有把同一个结论再解释一遍。

机器校验只能发现极长句和审核词堆积，不能判断中文是否自然。`oral_delivery_review` 的通过必须来自实际朗读后的重写，不能根据 validator 没报错自动填写。
